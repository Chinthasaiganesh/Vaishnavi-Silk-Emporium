# Troubleshooting

Use the API `x-request-id` returned to the browser when correlating requests with backend logs. Do not copy tokens, cookies, passwords, UTRs or customer screenshots into shared logs/tickets. Confirm environment/commit first; inspect read-only database state before corrective mutations.

| Issue / symptoms | Likely cause | Investigation | Resolution | Prevention |
| --- | --- | --- | --- | --- |
| API exits before listening; health unavailable | Missing `DATABASE_URL`, unreachable PostgreSQL, startup DDL failure, or missing required columns/tables. | Render start logs for fatal/init and schema-check entries; inspect DB connectivity and startup line; verify pooler URL/TLS. | Correct environment/network; back up then resolve schema mismatch with tested compatible DDL; redeploy. | Test against DB clone; monitor startup and health; use versioned migrations. |
| Inventory mismatch / product quantity disagrees | `Products.Quantity` is a mirror; manual SQL or legacy import bypassed Inventory; active holds or cancellation race. | Compare `CurrentStock`, `AvailableStock`, `ReservedStock`, mirror; inspect ACTIVE reservations/items, order status and InventoryAuditLog. Check `available+reserved=current`. | Reconcile from authoritative Inventory and known reservations/orders in a transaction; never infer stock from mirror alone. | Restrict direct SQL; use admin stock APIs; scheduled invariant checks and audit alerts. |
| Product says unavailable despite stock | Missing Inventory row (fail-closed), active reservations consume all available stock, or stale frontend polling. | Query product/Inventory and reservation expiry; call product/cart API; inspect admin inventory. | Create/reconcile Inventory via approved transaction; expire/release stale hold; refresh UI. | Ensure inventory record per product and monitor holds. |
| Stock reduction returns 409 | Requested current stock would be less than reserved amount. | Query `CurrentStock`, `ReservedStock`, active CheckoutReservationItems. | Wait for/resolve active checkout or choose a stock count >= reserved; do not force a negative available value. | Show active reservations in admin tools and warn before updates. |
| Product image/avatar/payment proof upload fails | Missing/invalid S3 endpoint/region/credentials/bucket, bucket permissions, unsupported MIME, >5 MB, image decode/dimension issue. | Check browser response/request ID and API storage errors; verify object policy/keys; distinguish 400 validation from S3 failure. | Configure correct S3-compatible endpoint and bucket access; re-upload allowed JPG/PNG/WEBP <=5 MB; avatar >=100x100. | Startup storage config validation, smoke upload per deploy, alarms, controlled retention. |
| Image URL exists but image does not display | Object deleted/moved, bucket not public, wrong public URL base, stale DB URL, provider outage. | Inspect DB `ImageUrl`, generated public URL, storage object key and bucket public policy; test URL without exposing sensitive proof. | Restore object or upload replacement; update DB through admin edit. For payment evidence, preserve access controls and avoid making it public unintentionally. | Verify bucket policy and object lifecycle; backup storage; do not delete based on URL mismatch. |
| Checkout says active payment session / cart API 409 | Active reservation locks cart. | `GET /cart` includes session; inspect reservation status and expiry; GET reservation state. | Complete order, explicitly release session before payment, or wait for expiry; then refresh cart. | Warn before reservation, idempotently release on cancel/expiry and monitor timer. |
| Checkout timer/QR disappears or amount differs | Reservation expired, browser cached QR mismatch/corrupt state, wrong `VITE_UPI_ID`, another browser session. | Check reservation `ReservationId`, server expiry/items, session storage key, build-time env and submitted key. | Start a fresh reservation and verify amount/reference before paying. If already paid, contact support; do not blindly pay again. | Keep QR tied to reservation ID; clear stale cache; alert on mismatch. |
| Payment proof uploaded but order absent | Storage upload happened before order transaction failed; reservation expired, idempotency key mismatch, DB conflict. | Correlate `x-request-id`, inspect order by user/key/reservation, DB error and S3 object key. | Retry only with same idempotency/reservation if still valid; otherwise support reconciles payment and creates an approved refund path. Clean orphan object only after proof it is not referenced. | Upload compensation or staged object cleanup; idempotency integration tests. |
| Order/payment status appears wrong | `OrderStatus` and `PaymentStatus` are separate; verification auto-advances PENDING to PROCESSING; rejected reservation order cancels. | Inspect Orders row, status history, lifecycle, payment review, cancellation/refund fields, order notifications. | Use permitted admin transition; don't patch DB without adding matching history/event. For canceled paid case, verify first then refund. | Add transition-level audit/alerts and order-flow tests. |
| Refund shown pending/blocked | Refund requires payment VERIFIED; refund transitions are state constrained. | Check `PaymentStatus`, `OrderStatus`, `RefundStatus`, cancellation evidence and admin logs. | Verify payment first; then allowed refund transition. External funds must be handled separately and reference recorded. | Admin checklist and ageing dashboard; explicit manual-transfer reconciliation. |
| Notification not redirected / unread count stale | Notification has no order/product link, latest list capped at 50, browser polling/event timing, or row not persisted. | Inspect notification's `OrderId`/`ProductId`, ownership/read state, API list/unread count, browser console/network. | Unlinked reservation notification correctly returns to center; refresh; mark/read through API. | Use stable foreign keys/event IDs, pagination and polling/realtime tests. |
| Duplicate/missing reservation notifications | `sendReservationNotification` dedupe is based on user/type/title/message and does not key by reservation ID. | Compare timestamps and notification rows for same owner across different holds; inspect cleanup logs. | Do not manually duplicate blindly; clarify this is presentation, not reservation state. | Add reservation id/event id to notification schema and unique dedupe key. |
| CORS/401 after deploy | Wrong `CLIENT_ORIGIN`, API base, cookie flags/domain, JWT expired or preview origin not allowlisted. | Browser network preflight, response headers, `x-request-id`, Render CORS logs, Vite built API URL, cookie flags. | Set exact HTTPS origin, `PUBLIC_API_ORIGIN`, project slug if appropriate; rebuild Vite for URL; redeploy both sides as needed. | Automated cross-origin smoke tests and env validation. |
| OAuth returns authentication_failed | Provider credentials/callback mismatch, `PUBLIC_API_ORIGIN` wrong, state/provider mismatch, missing verified email. | Check OAuth provider console redirect URI equals `/api/auth/oauth/{provider}/callback`; inspect sanitized callback stage logs. | Correct credentials/redirect URI/origin, redeploy, retry from `/login`. | Stage OAuth test and provider config inventory. |
| Translation remains English/source text | Current translation adapter returns original text; `INDIC_TRANS2_URL` is not called. | Inspect `translation.service.js` provider field and cache entry. | No configuration-only remedy; implement and validate provider adapter before promising translations. | Contract tests, provider timeout/fallback, cache versioning. |
| Product/order list is slow or memory-heavy | Full table/list fetching and in-process filtering, frequent polling, unbounded products/admin orders. | Check request duration/result size and DB query plans; watch memory/DB pool and request rate per tab. | Temporarily reduce clients/polling or narrow data; avoid repeated full refresh. | Pagination, indexed DB search, rate/conditional requests, load tests. |
| Seed gives unrelated products | `backend/src/seed.js` inserts legacy laptop/chair/speaker fixtures plus saree fixtures. | Check product names/created rows and whether seed was run on intended database. | Remove only confirmed test fixtures via admin or approved DB change; never run seed in production. | Make seed environment-gated and separate demo fixtures. |
| Database values look stale after code deploy | Runtime schema DDL may not run, app connected to wrong DB, frontend URL targets another backend, or app-level polling stale. | Compare DATABASE_URL host/ref without printing credentials; inspect backend boot logs, health DB version, frontend network host. | Correct environment/service target and restart; re-fetch data. | Environment banner, immutable release metadata and deploy smoke checks. |

## Incident Recovery Order

1. Preserve logs, deployed SHA/provider IDs, request IDs, DB snapshot and storage state.
2. Stop repeat payment/customer retry if financial state is uncertain; escalate through approved support process.
3. Establish source of truth for affected domain (Inventory, Orders, reservation, Notifications) before mutation.
4. Prefer provider rollback for application regressions; schema/data incidents need separate DB recovery review.
5. Verify invariants and user-facing state; document cause, impact, fix and test/prevention follow-up.
